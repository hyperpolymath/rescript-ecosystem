An unavailable URL establishes only that the repository was not accessible
during this check. It does not establish whether it was deleted, made private,
renamed, or transferred. Public repository-name search did not identify the
five missing standalone repositories under another owner; similarly named
third-party projects are not assumed to be copies. The tracked source inside
`developer-ecosystem` is the current recovery route. Its
https://github.com/hyperpolymath/developer-ecosystem/blob/main/rescript-ecosystem/MIGRATION.adoc[migration record]
states that consolidation is partial and that some packages diverge or duplicate
one another. That record includes historical build results, not a fresh build
verification for this handover.

For Bridge, `node --test tests/bridge_test.mjs` fails before running a test:
Node cannot import `lib/es6/src/Bridge.mjs` because that build output is absent.
This is a recorded verification failure, not a claim that the intended
framework behaviour is broken or complete.

== What has not been verified

Prior descriptions advertised versions, features, zero-dependency builds,
production readiness, and licence fallbacks. Those claims have not been
validated against the recovered source. `bridge-web-rescript` also has conflicting
licence signals: its `LICENSE` text contains additional terms while files and
metadata use `MPL-2.0` identifiers. The intended grant and any third-party
rights need review by the owner before presenting a licence to recipients.
The archived compiler repository must be assessed against its upstream
project's provenance and licences; GitHub currently does not label it as a fork.

An awesome list can index a public, useful project. It does not take over
maintenance of that project's code. Listing and stewardship are separate
decisions, and neither is appropriate for an unresolved pointer.

== Preparation required for each candidate

. Recover a complete repository with history, or establish an honest source
  snapshot and its provenance. Record the canonical URL and owner.
. Check copyright and actual licence files, including dependencies and any
  upstream code. Resolve inconsistent identifiers before making licence claims.
. Run the documented build and meaningful tests at a recorded commit. Report
  failures and unsupported platforms without concealing them.
. Remove broken badges and links; replace aspirational feature claims with
  implemented behaviour, limitations, and a short reproducible example.
. State the maintenance expectation, outstanding issues, and whether the
  recipient is being offered a code contribution, an index entry, or repository
  stewardship. Seek a willing recipient for the specific item.
. Only then prepare a focused contribution or transfer, preserving attribution
  and history. Do not archive or delete the original before the recipient has
  an accessible copy and the handover is confirmed.
